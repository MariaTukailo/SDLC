# Выбор интеграции с Календарем (iCal) для MVP

## Контекст и постановка задачи
Во втором раунде переговоров Заказчик попросил добавить функцию добавления мероприятия в личный календарь пользователя (для повышения удобства и снижения количества «забытых» событий). Интеграция требует дополнительно 1.5 недель разработки, при этом Заказчик отказался сдвигать дедлайн.

Основной вопрос: какую технологию выбрать для реализации этой функции, чтобы уложиться в сроки без сложной авторизации?

## Драйверы решения
1. **Простота реализации:** Решение должно быть реализовано быстро (без сложной OAuth-авторизации).
2. **Универсальность:** Работа на устройствах с разными ОС (iOS, Android, Windows).
3. **Сроки:** Функция должна быть реализована в рамках текущего дедлайна.

## Рассмотренные варианты
* Прямая интеграция с Google Calendar API (требует OAuth).
* Генерация стандартного файла `.ics` (iCalendar).

## Итог решения
Выбран вариант **«Генерация `.ics` файла»**. Это стандартный формат, который поддерживается всеми популярными календарями (Google Calendar, Apple Calendar, Outlook) и не требует сложной авторизации.

### Последствия
* **Хорошо:** Реализация проста и надежна, работает на любых устройствах.
* **Хорошо:** Функция реализована в срок (для ускорения верстки был привлечен junior-разработчик).
* **Плохо:** Пользователю нужно вручную открыть файл и подтвердить добавление (в отличие от прямой синхронизации).

### Подтверждение
Проверка наличия зависимости для генерации `.ics` (например, библиотека `ical4j`) в `pom.xml`. Проверка наличия кнопки «Добавить в календарь» на странице мероприятия.

## Плюсы и минусы вариантов

### Google Calendar API (прямая интеграция)
* **Хорошо:** Автоматическое добавление без участия пользователя.
* **Плохо:** Требует настройки OAuth 2.0, что усложняет разработку и увеличивает сроки.
* **Плохо:** Привязывает пользователя к экосистеме Google.

### Генерация `.ics` файла
* **Хорошо:** Универсально для всех календарей.
* **Хорошо:** Просто в реализации (нет сложной авторизации).
* **Плохо:** Требует одного лишнего клика от пользователя.

## Дополнительная информация
Адресует требование SRS: REQ-FUNC-010. 
Связано с ADR-004 (отказ от Spotify, который освободил ресурсы для этой функции). 
Детализация по срокам и бюджету (с учетом джуна) описана в отчете по лабораторной работе.
