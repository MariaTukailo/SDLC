# Отказ от интеграции с музыкальным API (Spotify) в MVP

## Контекст и постановка задачи
Изначально в архитектуре планировалась интеграция с Spotify для реализации функции «Совместный плейлист». Однако из-за жестких временных рамок возник вопрос: включать ли её в первую версию продукта (MVP)?

## Драйверы решения
1. **Сроки:** Интеграция требует настройки OAuth-авторизации, что не укладывается в текущий дедлайн.
2. **Бизнес-ценность:** Плейлист является второстепенной функцией по сравнению с базовым функционалом.
3. **Бюджет:** Дополнительные затраты не оправданы на этапе MVP.

## Рассмотренные варианты
* Реализовать интеграцию со Spotify в текущей версии.
* Отложить интеграцию на следующие версии (после релиза MVP).

## Итог решения
Выбран вариант **«Отложить интеграцию со Spotify»**. Функция «Совместный плейлист» (REQ-FUNC-006) переносится в бэклог.

### Последствия
* **Хорошо:** Освобождаются ресурсы для реализации более важных функций.
* **Плохо:** Пользователи временно не смогут совместно формировать плейлист.

### Подтверждение
Проверка обновленного SDD (удалены упоминания Spotify из раздела «Внешние интеграции») и обновленный план итераций в отчете.

## Плюсы и минусы вариантов
### Интеграция со Spotify (реализовать сейчас)
* **Хорошо:** Повышает вовлеченность гостей.
* **Плохо:** Требует сложной OAuth-авторизации и значительных временных затрат.

### Отложить интеграцию
* **Хорошо:** Экономит время и ресурсы для более важных задач.
* **Плохо:** Функция плейлиста недоступна в первой версии.

## Дополнительная информация
Адресует требования SRS: REQ-FUNC-006 (отложено), REQ-INT-011 (отложено). 
Связано с ADR-005 и ADR-006.
