# Использование PostgreSQL в качестве основной СУБД

## Контекст и постановка задачи
Приложению «Evently» необходимо надежно хранить связанные данные (пользователи, мероприятия, задачи, гости, бюджет). Требуется поддержка транзакций (ACID) и строгих связей между таблицами. Какую СУБД выбрать?

## Драйверы решения
* **Целостность данных:** Требуется поддержка ACID и внешних ключей.
* **Интеграция:** Необходима совместимость со Spring Data JPA (Hibernate).
* **Бюджет:** Использование Open Source решений.

## Рассмотренные варианты
* PostgreSQL
* MySQL
* MongoDB (NoSQL)

## Итог решения
Выбран вариант **«PostgreSQL»**, потому что он наилучшим образом обеспечивает строгую типизацию и целостность связанных данных.

### Последствия
* **Хорошо:** надежное хранение данных и поддержка сложных связей.
* **Плохо:** требует больше ресурсов памяти, чем SQLite, но это оправдано для production.

### Подтверждение
Проверка наличия зависимостей `spring-boot-starter-data-jpa` и `org.postgresql` в файле `pom.xml`.

## Плюсы и минусы вариантов
### PostgreSQL
* **Хорошо:** поддерживает сложные связи и транзакции.
* **Плохо:** большее потребление памяти.

### MySQL
* **Хорошо:** высокая скорость простых операций.
* **Плохо:** уступает PostgreSQL в работе с JSON.

### MongoDB
* **Хорошо:** гибкая структура.
* **Плохо:** отсутствие строгих связей (JOIN).

## Дополнительная информация
