# Выбор инструмента для построения UML-диаграмм и подхода к их трассировке

## Context and Problem Statement

В рамках проектирования системы «Evently» необходимо смоделировать динамическое поведение приложения с помощью UML-диаграмм (активности, состояний, последовательности). Диаграммы должны быть строго согласованы между собой и с ранее разработанными артефактами (SRS, use-cases.md, Use Case Diagram).

Основная проблема: выбрать инструмент, который обеспечит:
- строгое соответствие стандарту UML 2.5;
- наглядную трассируемость на требования SRS (REQ-xxx) и спецификации прецедентов (UC-xxx);
- возможность создания сложных, хорошо читаемых макетов с кастомными стилями;
- корректное хранение исходников и экспорт в проектную документацию.

## Decision Drivers

1. **Соответствие стандарту UML 2.5** — поддержка всех необходимых типов диаграмм и нотаций (ISO/IEC 19505).
2. **Качество визуализации** — возможность гибкой настройки макета для максимальной читаемости сложных сценариев.
3. **Трассируемость** — удобство добавления текстовых меток (UC-xxx, REQ-xxx) прямо на элементы диаграммы.
4. **Интеграция в документацию** — возможность качественного экспорта в форматы, встраиваемые в отчетность (PNG, PDF, SVG).

## Considered Options

### Вариант 1: Microsoft Visio
Профессиональный графический редактор с встроенными трафаретами UML 2.x.

### Вариант 2: PlantUML (диаграммы как код)
Описание диаграмм с помощью текстового DSL с автоматическим рендерингом.

### Вариант 3: draw.io (diagrams.net)
Бесплатный веб-ориентированный редактор с поддержкой UML-фигур.

## Decision Outcome

**Выбран Вариант 1: Microsoft Visio.**

Все диаграммы динамического поведения разрабатываются в Microsoft Visio с использованием стандартных наборов фигур UML. Исходные файлы хранятся в репозитории, а для включения в проектную документацию (SDD) выполняется экспорт в формат PNG/SVG с высоким разрешением.

### Краткое обоснование
Visio обеспечивает наилучший визуальный контроль над сложными макетами (особенно для диаграмм последовательности с множеством участников и диаграмм состояний с вложенными элементами). Это позволяет расставлять метки трассировки (UC, REQ) максимально аккуратно и читаемо, что критично для аудита архитектуры.

## Consequences

### Good
- Полный визуальный контроль над расположением элементов, что улучшает читаемость сложных сценариев.
- Строгое соответствие корпоративным и академическим стандартам оформления UML.
- Удобное добавление выносок и меток трассировки без нарушения структуры кода.
- Высокое качество экспорта в векторные (SVG) и растровые (PNG) форматы для документации.

### Bad
- Исходные файлы (`.vsdx`) являются бинарными или сложными XML, что затрудняет построчное ревью изменений (diff) в Git.
- Требует наличия установленного ПО или специализированного просмотрщика для редактирования исходников.

### Neutral
- Для обхода проблем с версионированием бинарных файлов в Git, в репозиторий коммитятся как исходные файлы, так и экспортированные изображения, чтобы история изменений была видна через картинки.

## Confirmation

Соблюдение решения будет проверяться по следующим критериям:
1. В репозитории присутствуют исходные файлы диаграмм и их экспортированные версии (PNG/SVG).
2. На всех диаграммах явно указаны ссылки на Use Cases (например, `UC-001`, `UC-002`) и требования SRS (например, `REQ-FUNC-001`).
3. Экспортированные изображения корректно встроены в раздел 3 SDD и Приложения проектной документации.
4. Стили фигур и линий единообразны across всех диаграмм в проекте.

## Pros and Cons of the Options

### Microsoft Visio
- **Good:** Идеальный визуальный контроль, профессиональные UML-трафареты, высокое качество экспорта.
- **Good:** Удобно расставлять метки трассировки и комментарии.
- **Bad:** Бинарные файлы плохо диффятся в Git.
- **Bad:** Требует лицензии или специфического окружения для редактирования.

### PlantUML
- **Good:** Отличное версионирование в Git (текстовый diff), единый стиль "из коробки".
- **Bad:** Сложно управлять макетом (layout) на больших диаграммах, фигуры могут "наезжать" друг на друга.
- **Bad:** Ограниченные возможности кастомной визуализации.

### draw.io
- **Good:** Бесплатный, работает в браузере, сохраняет в XML (лучше диффится, чем Visio).
- **Bad:** Меньше профессиональных функций для сложных UML-диаграмм по сравнению с Visio.
- **Bad:** При частом редактировании XML-файл становится громоздким и сложным для ручного чтения.
